# DATA3001 代码交付正式规划

更新：2026-11-22，Australia/Sydney。状态：本地架构迁移已实施，41个任务入口已接通。关键路径已实际验证；完整长时重训未验收，Gaussian受原运行预算检查限制，详见复现记录。

本规划让教授从一份README和一个Notebook进入项目，按需要查看结果、使用最终模型、重建图表或复现实验。目录按研究过程组织，数据、实验定义、冻结模型和历史结果保持可追溯。

正式入口固定为VS Code，前提改为教授已有可运行Notebook的Python3.12环境。第一个配置单元调用`code/environment/configure.py`，向当前Python安装锁定依赖、核对计算库并初始化入口。不再自动安装Python、启动Jupyter服务或绑定内核；已移除VS Code打开文件夹时的自动准备任务和专属解释器预设。当前科学代码支持Apple Silicon上的macOS 14及以上，其他平台适配另行验证。

当前操作以仓库根目录[README](../README.md)为准，实际检查见[复现验收记录](reproduction_audit.md)，逐文件对应见[迁移清单](migration_manifest.json)。下文保留已确认的设计与验收标准；其中原“待实现”描述是实施前状态，是否已接通以任务注册表及验收记录为准。

### 本轮实施决定

1. 按用户2026-11-22的补充要求，**archive保留原样，不删除**。该要求优先于下文早期“主目录不设archive”的最终清理目标。
2. 科学源码保持原字节。新执行入口在独立输出目录恢复原相对布局，保留源码和输入哈希检查；目录改变不触发算法重构。
3. 旧路径保留兼容链接，冻结结果目录保留其保护。每次新运行与原结果分开。
4. Notebook在一个环境配置单元后依次提供完整流程、数据预处理、Stage 1、Stage 2及最终模型与图表入口；每个模型有可直接运行的单元。安装由该配置单元直接负责。依赖版本保持锁定；Python兼容3.12系列，3.12.14为参考补丁版本。
5. 完整重新拟合沿用每项实验的固定输入与原合同。清洗重放另行核对；不能将复用固定输入写成从原始数据贯通重新生成全部上游资料。
6. 最终报告和已确认图表只迁移存放位置，正文与图像内容不改写。

## 1. 已确认的架构原则

| 决定 | 具体安排 |
|---|---|
| 以教授的使用目的组织入口 | README先给使用路径，Notebook按章节提供完整流程及各模型的直接运行单元 |
| 数据与程序分开 | `data/`只放数据、元数据及获取说明；所有可执行代码集中在`code/` |

| 保留必要检查 | `code/tests/`验证计算和实验规则；它与`data/test/`中的封存最终测试数据无关 |
| 本轮保留archive | 用户要求暂不删除，以便逐项对照迁移结果；必要输入的最终交付范围另据资产登记核对 |

## 4. Notebook模块与操作方式

**一个Notebook提供统一操作；模型算法保留在源文件中。** Notebook每个部分先说明输入、任务和输出，再调用对应程序，展示运行状态及结果链接。

| 模块（按Notebook顺序） | 教授运行哪个单元 | 输入与输出 |
|---|---|---|
| 环境配置 | 运行一个单元，向当前Python安装锁定依赖、检查计算库并加载入口 | 配置完成后可运行任意研究单元；不安装Python或切换内核 |
| 完整流程 | 运行一个总入口单元 | 重放开发数据清洗→首轮建模→次轮建模→报告图表与展示数据 |
| Data preprocessing only | 数据检查、清洗或Markov输入计数各有一个单元 | 数据身份、重放结果、输入计数及核对记录；不启动模型拟合 |
| Stage 1 only | 完整首轮单元，或每个模型的独立单元 | 对应训练、验证、预测和评分；保存原目标及权重 |
| Stage 2 only | 完整次轮单元，或五步骤下每个模型的独立单元 | 准备所属实验需要的原固定输入，展示完成状态 |
| 最终模型 | 加载冻结22成分模型，对指定起点预测 | 七天分布参数、终点样本和模型身份；不触发训练 |
| 报告图表 | 重建指定图表，或全部已交付图表与区域分析 | 图、源数据、数值检查及与报告结果的对应关系 |
| 已有结果汇总 | 运行汇总恢复单元 | 将原结果及来源复制到新的运行目录，不重新拟合 |

Notebook取消任务选择表及需要填写的`TASK`、`OPTIONS`变量。教授完成环境配置后，直接运行对应标题下的单元；各模型不依赖先执行其他模型单元。原实验共同拟合的B0/B1/B2保留在同一入口中，不拆改科学程序。

“Run All”会启动完整研究流程。完整流程或整阶段成功后，同一内核中其下属模型单元显示已有结果位置，不重复拟合；失败的分组不登记为完成。十二种成分数量的网络比较包含最初六种，其完成后六种比较单元也不重复训练。需要重新拟合已完成分组中的模型时，重启内核、运行环境配置，再运行该模型单元。该处理由`code/notebook_entry.py`完成，原实验调度和算法不变。

总入口先重放清洗，再按原顺序运行两轮实验。各模型仍读取自身合同固定的输入，新清洗文件不自动替换后续输入；图表继续使用已发布预测和冻结模型。Gaussian原运行时间检查仍生效，最近一次检查超过原上限，因此完整长时流程尚未通过端到端验收。

Notebook开头说明使用已有Python3.12，随后一个单元完成路径定位、依赖安装、环境检查和入口初始化。配置单元直接针对`sys.executable`安装依赖，不要求解释器位于项目`.venv`。如果更新了当前内核已经加载的包，提示重启当前内核后再次运行该单元；不要求切换到另一个内核。

`code/workflow.py`承担以下职责：

1. 按任务和配置确认输入依赖，显示本次将运行或复用的步骤。
2. 校验输入版本及哈希，缺失时说明获取或生成步骤；新运行不默默借用作者机器上的旧缓存。
3. 需要隔离的现有实验以独立进程运行，避免其进程级读取保护影响Notebook后续任务。
4. 每次执行保存配置、版本、种子、输入、输出、日志、耗时和状态。完成后打开结果位置。
5. 断点继续必须核对原运行身份与输入；配置改变则另建运行。完整重训与复用已保存结果分别记录。
6. 取消任务时终止相应子进程并保存中断状态；关闭页面不等于任务已经停止。

单项任务在新的Notebook内核中能够独立启动，不依赖先手动运行其他模型单元留下的变量。

## 5. 环境与配置方式

### 5.1 依赖安装

教授已有Python3.12及可运行的Notebook内核。`pyproject.toml`声明计算、绘图、文档和Notebook依赖；`uv.lock`锁定直接与间接依赖。`.python-version`保留3.12.14作为复现参考，配置记录实际补丁版本，不下载或升级Python。

首个配置单元通过`code/environment/configure.py`完成以下工作：

1. 检查Python3.12、支持平台和依赖清单。
2. 复用或自动准备固定版本的uv包安装工具；该工具保存在`.tools/`。
3. 按`uv.lock`导出临时安装清单，向当前`sys.executable`安装缺少或版本不符的依赖，核对包哈希。锁定文件不修改；无关已安装包不删除。
4. 安装项目代码，检查主要计算库和原生编译工具，记录实际Python和包版本。
5. 初始化Notebook实验入口，显示Ready。配置本身不读取研究数据、不运行实验。

如果安装替换了内核中已加载的包，需要重启当前内核后再次运行配置单元。新装包此前未加载时可直接继续。README和Notebook共用该入口，不维护第二套依赖列表。安装方式依据uv的[当前解释器安装说明](https://docs.astral.sh/uv/pip/environments/)及[锁定文件导出说明](https://docs.astral.sh/uv/concepts/projects/export/)。

原科学计算仍需要Apple Silicon、macOS14及以上和Apple编译工具。Windows、Linux和Intel Mac尚未完成适配验证。此前用于无Python安装和浏览器启动的`setup.sh`、`launch.py`与`START_HERE.command`保留为历史工程对照，不再属于教授的正式运行流程。

### 5.2 实验设置

沿用项目现有JSON配置形式，按用途分目录。每项实验保留独立设置，Notebook只负责选择配置及本次输出位置。

| 配置组 | 必须说明的内容 |
|---|---|
| `configs/data_preprocessing/` | 数据版本与源对象、R与D、几何、质量规则、时间容差、事件处理、字段、修复与资格规则 |
| `configs/stage1/` | 目标定义、7/30天或迭代设置、ID划分、基线、混合与邻域、速度状态、评分权重和随机种子 |
| `configs/stage2/` | 五步骤中的每项实验、时间角色、候选模型、拟合与选择规则、评分及对照依赖 |
| `configs/reporting/` | 图表输入版本、显示范围、抽样种子、R区域释放权重、概率区域及输出格式 |

`data/metadata/assets.json`登记数据身份、相对位置、获取方式和校验值；`saved_models/registry.json`登记模型结构、权重位置、哈希、来源运行和推荐状态。两者属于元数据，不包含执行程序。

配置分成“报告复现设置”和“自定义探索设置”。前者固定原实验定义；后者可以改参数，但保存新配置和新输出。预测时距、目标、数据角色、评分权重等改变会形成不同实验，不能仍以原报告结果命名。

## 6. 完整复现的运行顺序

**从清洗数据启动是主要复现路径；从原始资料启动在它前面增加下载与清洗。** 首轮和次轮共享合格数据准备，但次轮单项实验不需要先跑完整首轮。

1. 在已有Python3.12内核中运行配置单元，安装依赖并通过计算库检查；核对交付版本和资产清单。
2. 选择数据入口。原始路线固定GDP源对象及OISST等辅助资料，按历史处理清单生成当前清洗版本；清洗路线校验交付快照后直接继续。
3. 应用资格规则与必要修复覆盖表，生成目标对应的配对、完整漂流器ID角色及评价权重。不能仅调用轨迹读取函数就跳过资格检查。
4. 复现首轮已完成的基线、融合、空间信息、drogue比较、Markov迭代与一小时连续模型；保留各自的目标与评分设置。
5. 复现次轮Step1–Step3，然后按实验依赖完成Step4。时间划分、季节诊断、精确起点及位置误差分别保留输入和对照。
6. 使用Step4生成的训练坐标、查询坐标和角色表，完成Step5局部Gaussian、Gaussian mixture、原网络候选及成分扩展。完整比较还需重建其引用的对照评分。
7. 分别核对原算法选择和最终推荐。原选择流程保留单成分模型的结果；报告使用用户确认的22成分模型，不通过修改选择规则让两者表面一致。
8. 汇总预测与评分，生成四例分布、R区域综合分析、权重敏感性、模型比较及其他报告图表。
9. 执行计算与科学定义检查，对照原结果，保存复现报告。结果不同则列明对应输入、配置和数值差异，不覆盖原值。

原网络扩展复用了早期拟合。完整重训须从源数据和配置重建父实验，再按原复用规则生成扩展实验；快速路径可以读取冻结父产物，但运行记录要明确注明复用。

最终推荐模型为22成分混合密度网络，直接预测七天后去向。当前权重为：

现有`from_checkpoint()`能够按路径及校验值加载该模型；`load_selected_model()`读取原实验选择，会加载单成分模型。新Notebook必须从最终模型登记项明确加载22成分权重，并展示成分数与身份。原选择与验收文件保持不变。
