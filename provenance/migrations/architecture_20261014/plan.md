# Approved architecture migration execution plan

1. Freeze and independently back up every original file, record authority hashes and run the existing baseline suite.
2. Establish an installable src package and one explicit versioned asset catalog. Default access is read-only and final-test labels are restricted. Preserve scientific functions; block old frozen-run mutators.
3. Move data in checked batches without reserialisation. Preserve baseline and addendum separately, alongside source metadata, geometry, fixed splits and test partitions.
4. Move historical provenance and code without rewriting their bytes or hashes. Preserve whole report bundles and all historical planning material. Publish byte-identical controlled contract and final proposal copies.
5. Verify every original byte/symlink, external source copies, rule tests, current asset roles, ID assignments, target schemas and representative real calculations. New acceptance outputs must not alter frozen receipts.
6. Switch README and English stage guides to the new layout, retain verified backup and reversible journal, then review the whole change. No remote push and no cache/history deletion.

Failure gates: hash mismatch, missing asset, collision, changed scientific-function AST, altered split/geometry/labels, unresolved same-name table selection, mutated original receipt, unexpected test failure or unintended output write. Stop the affected batch and restore from the journal/verified backup.
