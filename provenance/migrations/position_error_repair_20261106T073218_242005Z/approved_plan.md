### 2.1 官方来源与采纳条件

主要候选为已审计的 AOML 原生单 drifter NetCDF：

1. `/phod/pub/lumpkin/hourly/v2.00/netcdf/drifter_<ID>.nc`。
2. `/phod/pub/buoydata/hourly_product/v2.01.1/drifter_hourly_<ID>.nc`，必须核查内部版本；不能凭目录名认定它更可靠。
3. v1.04c 原生文件用于可找到的历史记录交叉核对；NCEI 合并文件主要用于追溯和差异核验，不因其字段名写 standard error 就另乘 CI 系数。

已知异常的 ERDDAP／NCEI 版本保留为“现值来自哪里”的证据，不将它们相互一致视为正确尺度的独立证明。多个文件可能源自同一生产链，不能按多数票选择。

每个来源文件记录完整 URL、获取时间、字节数、SHA256、内部版本/history、定位方式、变量原始 dtype、单位、CI 语义、填充值及 packing 属性。建立**按来源文件与格式版本生效的解释规则**，不建立一个适用于全部 error 的缩放常数。

参考值只有满足以下条件才可以采纳：

- 官方来源身份与解码方式明确；字段的角度单位和 CI 幅度含义得到对应文档／作者方法及原生元数据支持。
- ID、时间、坐标匹配，且确认其对应的是同一位置估计，不能只因位置接近就搬用另一个版本的误差。
- 对 v2.00 老资料优先限于在其截止时间 **2020-06-30 23:00 UTC** 前已结束、且估计方法兼容的轨迹；仍存活、后续重新估计或版本关系不清的记录不能自动从旧版恢复。仅有坐标相同也不能解除这一限制。
- 对“目录 v2.01.1、内部 v2.00”的文件，按内部内容和来源证据处理；版本矛盾需记录，不能据目录名绕过旧版适用条件。
- 两个同样合格的来源若仍给出不能用已知存储精度解释的差异，标记 `reference_conflict`，不选择较大、较小或看起来更合理的一个。

v2.01 可能重新估计上一版本截止时仍存活的 drifter，见 [官方发布说明](https://www.aoml.noaa.gov/phod/gdp/hourly_data_release_notes.php)。因此，不为提高修复覆盖率而降低上述条件。

## 3. ID、时间和坐标的匹配规则

匹配分三道检查，全部通过才转入误差处理：

1. **ID 精确一致。** 使用整数或原始标识字符串，不把 WMO 号当 GDP ID，不按文件顺序匹配。
2. **时间精确一致。** 按文件声明的 calendar/epoch/单位转成 UTC；只消除可解释的机器舍入，不四舍五入到小时，不找“最近时刻”，不自动平移一天。不兼容的日历、时间单位或重复冲突时间进入待核查。
3. **坐标与存储精度一致。** 经度先统一到相同的 360° 周期表示；不以 cell、100 km 邻域或 error 大小作为匹配容差。本轮已确认的 float32 来源记录，以相同经度表示和原始 float32 精度转换后经纬度分别相等为通过条件；float64 等其他格式按明确记录的存储舍入界限核对，不从观测差异反推容差。额外报告 WGS84 距离差，仅作诊断。

`source_obs` 是本地原发布的行号，不能拿它直接索引另一版本的远程数组；远程匹配必须重新从 ID 和时间定位。

完全重复的远程行只有在坐标、两轴原值及语义一致时才能确定性合并，记录全部源行号；任一冲突即 `duplicate_conflict`。匹配必须是一条本地记录对应一个确定的参考观测，不允许 join 扩行。

坐标变化超过存储舍入范围时，标记 `coordinate_changed`；保留本地坐标和观测，不修坐标、不插值 error、不扩大容差。

## 4. 缩放、缺失值和异常处理

### 4.1 固定解码顺序

**识别原始缺失标记 → 只对有效原值解码 packing → 按明确单位转为度 → 检查误差语义与取值。**

- `_FillValue`、`missing_value`、NaN、Inf 在任何乘法前处理；缺失标记不参与缩放。[CF 缺失值规则](https://cfconventions.org/Data/cf-conventions/cf-conventions-1.7/build/ch02s05.html)
- 对实际声明的 `scale_factor` / `add_offset` 只应用一次。原生字段已经以度存储且没有 packing 时不补乘任何系数。
- 只有来源文档明确说明为旧整数 `10⁻⁵ degree` 编码时，才按该编码转为度；不因数值小或变量名含 error 就猜测单位。
- 已遇到旧文件把缺失标记写为类似 `-1.e+34f` 的字符串。只对已登记格式按严格数值语法解析，并转换到变量原始 dtype 后比较，保留原属性文本；不忽略该标记，也不用任意文本执行方式解析。无法解释的元数据进入待核查。
- 不开平方，不乘／除 1.96，不生成标准差、协方差、概率核或预测区域。这些属于后续建模假设。

### 4.2 逐记录、逐轴处理表

所有“采用参考值”均须先通过来源和匹配检查。

| 情况 | 修复补充表中的处理 |
|---|---|
| 现值与合格参考值相同 | 保留并标记 `verified_unchanged` |
| 合格参考值约为现值的 100,000 倍 | **直接复制参考值**，标记 `restored_scale`；不通过全局乘法生成结果 |
| 当前缺失或负值，但参考值明确、有限且为正 | 采用参考值，标记 `recovered_from_reference`；不是对负值取绝对值 |
| 原生参考也是填充值、NaN 或 Inf | 修复值留空，标记 `reference_missing` |
| 原生参考为负值 | 留空并标记 `reference_invalid`，不取绝对值 |
| 原生参考为零，未确认零的含义 | 原始零值保留在证据列；可用修复值留空，标记 `zero_unresolved`，不宣称位置完全无误差 |
| 仅一轴可恢复 | 保留该轴的已核实值；另一轴留空，`ci_2d_usable=false` |
| 来源缺失、语义不清、坐标变化或来源冲突 | 修复值留空，记录具体原因；不回退到未核实的现值 |
| 其他未解释的正值差异 | 保存候选值，标记 `unexplained_difference`；本版不自动采纳 |

倍率分类仅用于诊断，比较 1 与 100,000 时固定相对容差 `1e-6`，不加绝对容差掩盖小数差异。**符合倍率不构成来源可信的证据。** 实际采纳值保留参考文件的解码精度，不能取整成“更好看”的值。

两轴应来自同一条、同一估计版本的官方参考记录；不跨版本拼接一对 error。已有四条“经度缺失、纬度仍是旧尺度”的记录，纬度必须保持官方值，不能再乘十万。已有约 −9.99999 的负值按异常缺失链处理；若原生值为零，仍归入 `zero_unresolved`。

### 4.3 大值和可用性

- 不按经验上的 GPS/Argos 典型精度填补，也不按分位数截尾、设下限或删除大值。
- 必须报告每种定位方式、时期、来源版本的分位数和极端记录；统计上的极端不自动等于错误。
- 不满足明确有效范围、经度半宽达到 180°，或纬度对称区间越过 ±90°的记录，保留参考值证据并置 `geometry_review_required`，本版不认定可用于 CI；不得裁剪后重新称作原始 CI。
- `ci_2d_usable=true` 只表示两轴均通过本方案、可供后续定义 CI 使用，不证明联合覆盖率达到 95%，也不自动批准 E8。
- error 不可用不等于位置不可用。所有原合法轨迹、配对和终点仍保留；本轮不重新计算 position_ok、mapping_ok 或样本资格。

每个 worker 只写自己的临时文件，完整下载并核验后才发布；只有父进程汇总、验证并发布最终 manifest。缓存缺块或失败文件不能当作完成文件使用。

未来只有显式指定 `base_version + repair_manifest_sha256` 才能读取修复视图；不修改默认数据路径，不把 overlay 再作为原始输入。已批准版本不覆盖重写，重新执行同规则应得到相同逻辑表及内容校验值。基础版本不符、重复应用或 key 超出范围必须拒绝。

回滚只需停止引用补充表；原数据无需恢复。此次审批**不包括把补充表合并为新的全库 canonical 版本或接入模型**。

## 6. 验证方法与验收标准

### 6.1 工程验证

先建立独立的小型规则测试：双重缩放、缩放前缺失识别、字符串填充值、零／负值、单位不明、浮点舍入、经度周期、错误 ID、错时刻、一日偏移、重复冲突、改动坐标、版本冲突和单轴可用。期望值由明确输入定义，不以主程序输出反写答案。

再用现有证据作回归核查：

- 三个 ID 的 1,604 个训练终点、3,208 个正值：采纳值应与已核实的官方原生值一致，不能再次缩放。
- 19 个 ID、65 个诊断观测：四个保持旧尺度的纬度值不得放大；负值不得变正；零值不得变成可用 CI；已确认坐标变化的旧 GPS 参考不得移植 error。
- 起点和终点使用同一规则；不能只验证终点而遗漏同一 key 在另一配对中的使用。

执行独立验证器，重新从缓存原生文件解码、定位及比对，不只读取修复程序写出的“成功”标记，也不调用主程序同一套匹配／解码函数生成期望结果。对全部已采纳值逐条复核；审查全部例外和每类修复的代表案例。独立算法路径不等同于已获得官方生产者确认。

### 6.2 硬验收项

| 项目 | 必须达到的标准 |
|---|---|
| 范围完整 | 355,247 个目标观测均恰好一行，0 个遗漏、额外 key 或重复 key；执行时以冻结目标清单复核 |
| 来源可追溯 | 100% 已采纳字段可追溯到官方文件 hash、具体源行及确定的转换规则 |
| 正确匹配 | 100% 已采纳值通过 ID、时间、坐标和估计版本检查；模糊匹配为 0 |
| 数值一致 | 全量独立核验通过，采纳值与参考的声明精度相符；未解释差异为 0 |
| 异常透明 | 每个未修复字段都有明确状态；负值、填充值、未确认零值进入可用 CI 的数量为 0 |
| 数据不变 | 338 个基础文件 hash、数据 manifest、训练 key、配对、现有 contract／阶段记录与执行前一致 |
| 可复现 | 固定缓存的重复执行及单／双 worker 输出逻辑一致；不依赖网络文件顺序 |
| 无越界 | 不读锁定 final-test；不读本轮外层 endpoint error；没有训练、CV、预测或评分调用 |

**100% 核验覆盖不等于 100% error 必须变成可用。** 真实缺失或未解决的记录允许留空，不能为了通过验收硬填值。

报告分别给出：来源文件获取率、唯一观测匹配率、逐轴可恢复率、两轴共同可用率、各状态数量、按 ID／时期／定位方式／来源分层的比例。分母同时列出目标观测数和受影响配对数，避免重复配对把修复覆盖率夸大。

结论分为：`VERIFIED_COMPLETE`（全部目标已核验、无待解决来源问题；仍可有明确缺失）、`VERIFIED_PARTIAL`（已采纳部分可靠，剩余事项及可用性限制完整列出）、`FAILED_VALIDATION`（身份、匹配、数值或不变性检查失败）。网络预算内未完成的目标标记 `not_fetched_budget`，只能是部分完成，不当作真实源数据缺失。

上述通过仅代表数据修复交付可靠，**不代表 CI 已校准，也不代表预测得到改善**。不把覆盖率或 Brier/ES 作为挑选修复规则的依据；任何模型实验仍需单独确认。

## 7. 批准后的执行顺序和预算

1. 冻结批准版本、目标 key 和输入 hash；开发修复器与独立验证器，完成规则测试。
2. 先处理现有 19 个诊断 ID 的授权 key；覆盖 Argos/GPS、倍率异常、单轴缺失、负值、坐标变化和元数据冲突。试跑只验证数据流程，不训练模型。
3. 试跑核验通过，且实测资源外推在预算内，继续同一规则处理全部 338 个 ID；不能看覆盖率后放宽匹配／来源条件。
4. 全量独立复核，生成补充表、例外清单、尺度对照和报告，向用户汇报；此处结束，不接着运行 E8。

建议预算：最多 2 个网络 worker，单次请求 45 秒超时、最多 3 次有限重试并记录；试跑最多 20 分钟，全流程资源运行最多 2 小时（不含开发时间），网络获取最多 8 GiB、新文件最多 10 GiB、内存峰值 4 GiB。优先复用已校验缓存。以上是待批准的资源上限，不是已测得工期。

触及预算、出现输入身份变化或系统性匹配错误时，保存检查点和原因，停止推进并汇报。不得通过删掉目标 key、改单位假设或放宽坐标容差凑齐“完成”。
